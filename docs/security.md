# 보안 자세 (Security posture)

- **Trust-boundary redaction** — failed tool results (local tools and proxied tools whose upstream reports `isError`), thrown errors, and resource/prompt error envelopes pass through `util/redact.ts` before they reach the host LLM, so `glpat-*`, `Bearer <token>`, `oauth2:<secret>@…` URLs and `access_token / refresh_token / device_code` JSON fields never reach it verbatim (INV-13). Successful tool results are the tool's real output and are not rewritten; tools keep secrets out of them themselves — git URLs have their userinfo removed where they are read (INV-15).

- **Path-traversal rejection** — `projectDir` / `targetDir`은 MCP dispatch 경계에서 zod-refined됩니다. `..`, NUL, symlinked parent는 파일시스템 접근 전에 `invalid_input` / `invalid_parent`로 거부됩니다.

- **Attach stays inside the project** — links in the project (committed in a cloned repo, or made by hand) cannot redirect attach writes outside the project folder or into `.git/`; attach fails with `attach_failed` instead (INV-14).

- **Project token file** — `<project>/.verse8/token` can arrive with a cloned repository or be swapped for a link, which would make the tools act as somebody else's account. It is read only when it is a regular file that git does not track, and a check that fails counts as a refusal, never as "safe"; a skipped file is reported by `verse8_status` as `projectTokenRefused` with the reason. To keep the file from getting tracked at all, `verse8_attach` lists it in `.verse8/.gitignore`, `verse8_checkpoint` never commits it, and the pre-commit hook rejects a commit that adds it (INV-16).

- **Clone-command safety** — `git clone`은 항상 `execFileSync` argv-array 형태로 실행됩니다. GitLab PAT는 `parseCloneCommand`로 파싱되며 절대 셸에 보간되지 않습니다.

- **Host allow-list** — 모든 env-driven base URL은 `*.verse8.io` + loopback에 대해 caller별 정책 predicate로 검증됩니다. 단일 진입점 `parseOverrideHost` (low-level URL parser)만 공유하고, 정책 결정 (auth / proxy / web-editor)은 caller 별로 분리되어 있습니다.

- **Failure atomicity** — `applyAttachmentArtifacts`는 단계별 reverse op를 기록합니다. 중간 단계 실패 시 LIFO 순으로 이전 쓰기를 rollback 해 디스크에 어떤 부분적인 attach 흔적도 남기지 않습니다.

- **Publish guard** — `prepublishOnly`가 `scripts/prepublish-guard.sh`를 실행해 `npm pack` 타볼에서 `glpat-*`, `Bearer <token>`, `"access_token":"…"`, `VITE_AGENT8_ACCOUNT=0x<hex>`, `*.map` 파일명을 스캔. 매치가 있으면 publish 거부.

- **Secret-pattern fuzz tests** — `tests/unit/redact.test.mjs` + `tests/unit/dispatchRedaction.test.mjs`가 8 가지 secret shape에 대해 redactor + dispatch envelope wrapping을 회귀 검증.

## Invariants

Promises that must survive any refactor. Each test case or source line that enforces one carries a tag comment `<ID>: <title>` (`//` in TS/JS, `#` in `tests/smoke.sh`), e.g. `// INV-3: URL overrides are host-validated`. To find them:

```bash
git grep -nE '(INV|MCP-UP)-[0-9]+:'   # every tag
git grep -n 'INV-3:'                  # one invariant
```

When you change or move a tagged test, move its tag with it. A new invariant takes the next free number.

| ID | Invariant |
|---|---|
| INV-1 | **The token never hits a shell.** The GitLab PAT is parsed by `parseCloneCommand` and passed only as `execFileSync` argv. A backend-supplied slug containing `..`, `/`, `\`, or NUL is rejected |
| INV-2 | **`.verse8/project.json` carries no secrets.** The payload is `{version, projectId, attachedAt}` only |
| INV-3 | **URL overrides are host-validated.** Every env-driven base URL goes through `parseOverrideHost` plus a per-caller `isAllowed*` predicate for its allowed hosts. Services with defaults fall back to those defaults. IP asset endpoints require HTTPS on verse8.io, its subdomains, loopback, or exactly vicoop-router.fly.dev. Invalid IP asset configuration fails before any request |
| INV-4 | **Skill merge precedence is `core > vendor > cache`.** `listSkillResources` calls `Map.set` in cache → vendor → core order, so the last write wins |
| INV-5 | **`.env` ACCOUNT/VERSE is immutable once set.** A mismatch returns `mismatch-preserved` with a hint pointing at `verse8_attach({overwriteEnv: true})` |
| INV-6 | **Skills outside the bundle are never touched.** `writeSkillFiles` writes only to directories named after bundled skills. `pruneOrphanedSkills` and retiring an inactive plugin's skill remove a non-bundled skill only when its `SKILL.md` carries an unedited verse8-mcp hash marker, and then delete only that `SKILL.md` (the directory only if it is left empty), never other files in it. An attach rollback undoes only the file changes that run made: it restores the exact bytes and file mode of each `SKILL.md` it replaced or removed (writes go through a temp file and rename), and removes a skill directory only if that run created it. `overwriteAllSkills` is the one escape hatch: it overwrites bundled-name directories even when the user edited them |
| INV-7 | **Overwrite flags stay in their lane.** `overwriteAllSkills` affects skills only, `overwriteEnv` affects `.env` only |
| INV-8 | **The V8 commit format is an on-wire contract.** `buildV8CommitMessage` is deterministic, the parser accepts everything the builder emits, and structurally drifted messages are rejected |
| INV-9 | **Narrative lives inside `<V8AssistantMessage>`.** `<problemStatement>` / `<workSummary>` are emitted there and duplicated into the `<V8AgentMessage>` JSON. The legacy `## Problem` / `## Work` layout is parsed but never emitted |
| INV-10 | **Proxy session retry is single-shot.** On session expiry the cache is evicted and the call reinitialized and retried once; two consecutive failures surface as-is |
| INV-11 | **Tool discovery is token-gated, not cwd-gated.** With a token, `verse8_checkpoint`, `verse8_preview` and proxy tools are listed; the project is re-validated at call time |
| INV-12 | **The plugin package gate fails closed.** A vendored plugin with a malformed `requiresPackage`, a missing or unparseable `plugin.json`, or non-empty `tags` is inactive, and a missing `package.json` is an empty dependency set. A scope nobody can read never degrades into "every project" |
| INV-13 | **Failure results carry no known secret shape.** `dispatchTool` runs every failed tool result through `redactValue` before it reaches the host: `ok: false`, and a proxied result whose upstream answer has `isError: true`. Success results pass through untouched. Backend text shortened for a hint (error bodies, error strings, serialized 2xx bodies that failed a shape check) goes through `redactHead`, which redacts before it cuts, and a token grant that succeeded without a clone URL reports key names only, never the body |
| INV-14 | **Attach writes never leave the project folder.** Every write, mkdir, delete and rename that `applyAttachmentArtifacts` makes (hooks, `AGENTS.md`/`CLAUDE.md`, `.verse8/`, `.claude/skills/`, `.env`, both `.gitignore`s, and their rollback) goes through `util/projectWrite.ts`; so does the `.env` self-heal in `verse8_checkpoint`. It refuses a target when any existing component, the target itself included, is a link that leads outside the project (a dangling link is followed hop by hop and judged by where it points, its target walked component by component as a POSIX kernel does, so `..` steps up from the real folder a preceding link led to rather than being folded away as text; on Windows the text-folded reading is checked as well, and both readings must stay inside), or a link from the working tree into the real `.git/` folder, and attach then fails with `attach_failed` naming the link and where it points. Links that stay inside the project are allowed. Content that would be written back (`.env`, a `SKILL.md` snapshot for rollback) is never read through a link that leads outside, so outside content is never copied into the project. A hook that attach replaces gets its bytes and mode back on rollback. A unit test fails when one of those source files calls a mutating `fs` function directly. Two exceptions, both the user's own setup rather than anything a clone can carry: a `core.hooksPath` (absolute or relative) that resolves outside the project, and a hooks folder under `<project>/.git` whose real location is outside (`.git` or `.git/hooks` is a link). Hook writes go to that folder, confined to it |
| INV-15 | **Git URLs in tool results carry no credentials.** A clone URL from the backend and the origin URL read from a local repo have their userinfo removed where they are read (`stripUrlCredentials`), so `gitUrl` and `project.gitlabRemote` never carry the project token. The `git clone` command that does carry it stays internal |
| INV-16 | **The project token file is never read through a link or from git.** `<project>/.verse8/token` is used only when `.verse8` and the file are not links (Windows junctions included), the file is a regular file, and git says it is untracked. "Untracked" has exactly two forms: `git ls-files --error-unmatch` exits 1 (matched case-insensitively, so `.verse8/Token` in the index counts as tracked), or git answers "not a git repository" and no `.git` entry exists in the project folder or any folder above it — git gives that same answer for a damaged repository, which the second condition catches. The check asks the repository at the nearest `.git` only (discovery is stopped there with `GIT_CEILING_DIRECTORIES`), so a damaged repository inside another work tree is not answered for by the outer one; it runs with `--no-literal-pathspecs` and without any inherited `GIT_*` variable, since those can point git at another repository or index, change how the pathspec is read, or inject config. Every check that fails instead of answering refuses the file: any other git failure such as exit 128 for unsafe ("dubious") ownership, a corrupt index or a bad config (`git_check_failed`), git missing or timing out (`git_unavailable`), an `lstat` or read error other than "no such file" (`unreadable`), and a file that is no longer the one that was examined when it is opened (`symlink`). A refused file is skipped, reported by `verse8_status` as `projectTokenRefused` with that reason, and never deleted by `verse8_logout`; logout answers `logout_incomplete` when a token file could not be deleted or was refused only because it could not be checked (`unreadable`, `git_unavailable`, `git_check_failed`), since that file may be used again later, and also when another project folder whose token file this server has used still has it. Prevention: `.verse8/.gitignore` (written by `verse8_attach`) lists `/token`, `verse8_checkpoint` drops a staged `.verse8/token` from its commit (any letter case; a staged removal is kept), and the pre-commit hook rejects a commit that adds or changes one at any depth. The hook lets git match the path (plumbing commands, so the size of the commit and `diff.*` settings do not matter), rejects with the git error when git cannot answer, and prints staged paths as quoted data only: the unstage command it suggests is fixed text, because a path from a cloned repository pasted into a shell command could carry `$(…)`. All token lookups go through `resolveToken`, and no tool result or log carries the token value — only its source and file path |
| MCP-UP-1 | **`verse8_upload_asset` talks only to the allow-listed backend.** The URL comes from `getAgent8BackendBaseUrl()` gated by `isAllowedAgent8BackendBase` |
| MCP-UP-2 | **`cdnPath` traversal is rejected before the network.** `..`, a leading `/`, empty segments, NUL, and a `filename` containing path separators |
| MCP-UP-3 | **`ATTACHMENT_EXTS` is the pre-network extension gate.** Kept in sync by hand with `planetarium/agent8-backend/src/config/constants.ts` |
